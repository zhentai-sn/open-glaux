# Glaux 前端视觉交互设计纲领

> **用途**:回答"Glaux 的界面为什么长这样、为什么这样动"。所有新 UI 工作(设计稿、SDD、实现、评审)对照本纲领;与纲领冲突的设计要么改设计,要么先修订纲领。
> **性质**:活文档,原则层。具体数值、组件契约、验收标准分别归 token 文件与各 Feature SDD——**纲领管方向,SDD 管契约**。
> **来源**:蒸馏自 [产品纲领](../roadmaps/charter.zh-CN.md) · [需求清单](../requirements.zh-CN.md) · [IDE 前端设计稿 2026-07-06](2026-07-06-glaux-ide-frontend.zh-CN.md) · [双模式外壳设计 2026-08-13](2026-08-13-001-dual-mode-shell.zh-CN.md)(评审通过)。

---

## 0. 一句话

**Glaux 的界面是"让不会写代码的研究者,信任一个替他动手的智能体"的界面**——一切视觉与交互决策都从这句话推导。

## 1. 三重根基

纲领按三个层次组织,层次之间是推导关系,不是并列关系:

| 根基 | 回答的问题 | 原则 |
| --- | --- | --- |
| **哲学性**——界面的世界观 | 这个界面相信什么? | G1–G6 |
| **美观**——世界观的可感形式 | 相信的东西长什么样? | G7、G11、G12 |
| **易用**——形式对人的兑现 | 用的人是否毫不费力地得到它? | G3、G8、G9、G10、G13 |

哲学决定气质,美观让气质可感,易用把气质兑现成体验。评审顺序也照此:先问哲学对不对,再问美不美,最后问顺不顺手——**顺手但说谎的界面,在 Glaux 是坏界面**。

---

## 2. 哲学性:界面的世界观

### G1 · 两类用户,双模式恒定
界面永远同时服务两类人:**用户 B**(非计算研究者,产品的存在理由)与**专家/开发者**(内部与深度用户)。解法不是折中,而是**双模式**:Focus(对话优先,默认)与 Workbench(IDE 式,全量)。**默认值即产品立场**——任何新用户第一眼看到的必须是 Focus。

### G2 · 对话优先,意图入口唯一
B 的第一动作是描述研究目标,不是学习界面分区。Focus 空状态就是一个输入框 + 示例任务卡;**示例即教学**,替代 onboarding 文档。任何要求 B "先找到某个面板"的设计都违反本条。

### G4 · 舞台一等:同步核对回路
Glaux 与 Codex 类产品的刻意分野:Codex 是"提交后走开"的异步任务农场,Glaux 的核心场景是**同步核对回路**——跑一小批 → B 十分钟点选核对 → 建立信任。因此图像舞台与无代码修正手势(点选/圈画)是一等公民,任何模式都不可省;修正即时生效并标记人工来源。这也是人机责任边界的表达:**智能体动手,人核对;界面的职责是把"核对"变得便宜**。

### G5 · 信任必须可见
信任 = 透明 + 可复现 + 校准过的不确定(需求清单 §3.3),这三样都是 **UI 一等公民**,不是日志里的细节:
- **三态守卫不静默**:置信(绿)正常展示;歧义(黄)追问澄清;超范围/缺标定(红)显式拒绝——绝不静默错跑、绝不静默出 0。
- **来源徽标**:每个结果标注 `agent` / `human`(修正后),全链路可见。
- **存疑主动暴露**:低置信区段在舞台上高亮并引导核对,而不是藏在均值背后。
- **语义色与交互色严格分离**:good/warn/crit 只表达置信语义,accent 只表达可交互——两者永不混用。

### G6 · 数据真实性:绝不造假
Mockup 与 demo 用真实验证数值;影像若为示意渲染必须显式标注,真实部署替换为真图并去标。**绝不用假数字冒充测量结果**——对一个卖"可验证"的产品,界面里的每个数都是产品承诺的一部分。

## 3. 美观:世界观的可感形式

### G11 · 秩序之美:环境感的深色冷调
Glaux 的美学立场是**科学仪器的秩序之美**,不是消费软件的装饰之美:
- **深色冷调基底有功能理由**:医学影像在暗环境审读——深色底消除眩光,让灰度影像的动态范围与彩色叠加的对比最大化。美观在这里是"看得准"的副产品,这正是它耐看的原因。
- **色彩即语义,零装饰色**:界面上每一种颜色都有唯一含义——智能体紫、边界蓝/珊瑚、ROI teal、置信绿/黄/红、交互蓝。不存在"为了好看"而出现的颜色;新颜色的引入等于新语义的立项,须过纲领评审。
- **层级靠明度与留白,不靠线框堆叠**:文本四级明度(bright/ink/mid/faint)承担主要层级;分隔优先用空间,其次用细线,最后才是底色块。
- **克制即高级**:圆角 4/6/8px、细描边、无阴影堆叠、无渐变装饰。界面越安静,数据越响亮。

### G7 · 仪器质感
数值一律等宽字体 + `tabular-nums`(列对齐),单位与标定(mm、mm/px、CF)永远伴随数值出现,无单位的裸数不允许上屏。仪器面板的美来自"每个读数都可信、每列都对齐"。

### G12 · 动效即因果,不是装饰
动效在 Glaux 只有一个正当职责:**解释因果**——什么变了、从哪来、到哪去。对 B 这尤其是刚需:舞台为什么展开(因为任务卡片产出了结果)、叠加为什么变色(因为我刚修正了边界)、追问为什么弹出(因为我的话有歧义)——这些因果链靠动效可感,靠文字不可感。反过来,**不解释任何因果的动效就是噪音**,一律不做。详细规范见 §5。

## 4. 易用:形式对人的兑现

### G3 · 复杂度按需浮现,并有反长回约束
工作产物(度量、日志、明细)在任务卡片与舞台中按需出现,不预先铺开常驻面板。配套硬约束(**反长回规则**):新能力默认 Workbench 独占,进入 Focus 必须显式设计并更新对应 SDD——防止 Focus 逐渐长回一个 IDE。

### G8 · 单一状态真相源,布局只是视图
领域状态(会话、当前图、度量、原语、来源)全部住在单一 store;Focus/Workbench 是同一状态的两种投影。**切换模式、切换语言、重排布局都不得丢失任何状态**——为此智能体消息以 i18n 键存储(切语言即重译,历史不丢),模式切换零请求、零数据搬运。

### G13 · 反馈无空窗
用户的每个动作在 **100ms 内**必须有可感知回应(哪怕只是按压态);预计超过 **300ms** 的操作出加载态(骨架/进行中标记),超过 **1s** 的出过程性反馈(如四步逐项打勾)。**界面永远不允许"点了没反应"的空窗**——B 无法区分"在算"和"坏了",空窗直接消耗信任。本地能即时估算的(如拖动边界重算 IMT)先给估算值,权威值回来后校正并标注。

### G9 · 双语一等
全部 chrome 与智能体动态发言中英即时切换;数值、单位、标识符、路径不翻译。新增任何用户可见文案必须走 i18n 键,禁止硬编码。

### G10 · 可达性是底线不是加分项
全交互键盘可达、可见 focus 环、尊重 `prefers-reduced-motion`(见 §5 M5);画布叠加(LI/MA/ROI)不得仅靠颜色区分——虚实线型与标签并用,色觉障碍者可辨。

## 5. 动效规范(G12 的展开)

### M1 · 每个动效回答三问
立项任何动效前先回答:**什么变了?从哪来?到哪去?** 答不全就不做。典型正例:任务卡片产出结果 → 舞台自右侧展开(结果"从卡片流向舞台");点击卡片"核对存疑段" → 舞台对应区段一次性脉冲高亮(注意力"从卡片引向区段")。典型反例:入场彩带、悬停弹跳、循环光效。

### M2 · 时长与缓动
| 场景 | 时长 | 缓动 |
| --- | --- | --- |
| 微交互(按压、hover、勾选) | 120–160ms | ease-out |
| 面板/舞台/抽屉开合 | 200–280ms | ease-out(入)· ease-in 且更短(出) |
| 模式切换(Focus ⇄ Workbench) | ≤320ms 交叉淡入淡出 | ease-in-out |
| 流式文本/逐步打勾 | 跟随数据节奏 | 线性渐现(opacity) |

节奏立场:**快而克制**。所有入场用减速曲线(世界迎向用户),退场更快更干脆(不挽留)。模式切换刻意用朴素 crossfade——两模式是"同一世界的两种视角"(G8),不做翻转/缩放等把切换戏剧化的效果。

### M3 · 过程感即信任感
智能体的工作过程用动效呈现节奏:流式文本渐现、四步(Interpret/Calibrate/Segment/Measure)逐项打勾、进行中骨架。这是 G5(信任可见)在时间维度上的延伸——**让 B 看见"它正在认真做"**,而不是黑箱转圈后突然给答案。

### M4 · 医学画面上的动效纪律
舞台(影像画布)上的动效最克制:引导注意力用**一次性脉冲**(如存疑段高亮闪一次即恒定),**禁止任何持续循环动画**——审读画面上循环闪烁会干扰核对且不专业。修正手势的反馈(拖动手柄、边界重绘)必须跟手零延迟,不加缓动——**直接操纵的对象不许有惯性**。

### M5 · `prefers-reduced-motion` 尊重到底
开启时:位移/缩放类动效全部关闭,仅保留不透明度渐变与状态的瞬时切换;流式文本改为整段出现。功能语义(什么变了)必须在无动效时依然完整——动效是因果的**放大器**,不是唯一载体。

### M6 · 性能底线
只动 `transform` 与 `opacity`(合成器路径),不动布局属性;动效不得阻塞输入;掉帧的动效比没有动效更伤质感——达不到流畅就降级为瞬时切换。

### 动效 token(共享层)
时长与缓动进 tokens.css,禁止组件内写死:`--motion-fast: 140ms` · `--motion-base: 240ms` · `--motion-slow: 320ms` · `--ease-out: cubic-bezier(0.2, 0, 0, 1)` · `--ease-in: cubic-bezier(0.4, 0, 1, 1)` · `--ease-in-out: cubic-bezier(0.4, 0, 0.2, 1)`。落地随首个使用动效的实现计划进 tokens.css。

## 6. 视觉语言(token 分层)

Token 真相源在 [tokens.css](../../frontend/src/styles/tokens.css),自 2026-08-13 起按两层理解:

| 层 | 内容 | 归属 |
| --- | --- | --- |
| **共享层**(跨模式恒定) | 结构底/文本层级/描边色 · 智能体紫 `--agent` · 边界叠加 LI/MA/ROI(沿 `overlay.py` 约定) · 语义色 good/warn/crit · 排版(system-ui 栈、等宽数值、13px 正文/11px 区域标题) · 4/6/8px 圆角 · **动效时长与缓动(§5)** | 本纲领 + tokens.css |
| **模式层**(布局尺度) | 活动栏 48px、侧边栏 250px、Agent 栏 340px 等 → 归 Workbench;对话流列宽 ≤720px、舞台占比等 → 归 Focus | 各模式的 Feature SDD |

遗留待办:`--accent/--status` 的"临时统一紫"(tokens.css 内注释)属主题方案,待未来主题 SDD 处理,不阻塞当前工作。

## 7. 纲领的效力与修订

- 新设计稿 / Feature SDD 的评审清单第一项:逐条对照 G1–G13,标注冲突或豁免;含动效的设计另过 §5 三问(M1)。
- 纲领修订走与设计文档相同的评审;修订必须写明动机与被替代的旧原则。
- 纲领与 SDD 冲突时:以纲领为准修 SDD,或先修纲领——不允许带着冲突实现。
