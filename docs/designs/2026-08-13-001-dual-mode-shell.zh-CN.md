# SDD · 双模式外壳(Focus / Workbench)

> **用途**:回应"VSCode 式设计对目标群体太复杂"的评审意见——参照 OpenAI Codex 的对话优先形态,新增 **Focus 模式**作为默认界面,现有 IDE 布局降级为 **Workbench 模式**,顶栏一键无损切换。
> **日期**:2026-08-13 · **状态**:reviewed(设计稿 2026-08-13 评审通过;上位原则见[前端设计纲领](frontend-design-charter.zh-CN.md)) · **依据**:[需求清单 §1.1/§2/§3.2](../requirements.zh-CN.md) · [Feature SDD feats/01](../sdd/feats/01-dual-mode-shell/README.md) · [设计稿 mockup](../sdd/feats/01-dual-mode-shell/mockup.html)
> **半衰期提醒**:对 Codex 形态的参照基于 2026-08 的产品现状;Codex 自身迭代不影响本设计的原则层(对话优先、复杂度按需浮现)。

---

## 0. 一页纸

**问题**:首要用户 B(需求清单 §1.1)是"不会写宏/脚本、没有计算影像同事"的研究者。现前端([设计稿 2026-07-06](2026-07-06-glaux-ide-frontend.zh-CN.md))是完整 IDE 隐喻:活动栏 + 侧栏 + 编辑器 + 底部面板 + 终端 + dockview 可停靠拖拽。这套隐喻的母语者是开发者;B 打开的第一眼是"这是给程序员的工具",与产品承诺"用自然语言描述研究目标"直接冲突。

**解法**:外壳分两种模式,共享同一份领域状态:

| | **Focus(新增,默认)** | **Workbench(现状,改名)** |
| --- | --- | --- |
| 隐喻 | 对话(Codex / Claude 式) | IDE(VSCode 式) |
| 主体 | 居中对话流 + 按需展开的图像舞台 | dockview 四区 + 活动栏 + 状态栏 |
| 面向 | 用户 B(非计算研究者) | 专家、内部开发、demo 深潜 |
| 复杂度 | 被召唤出来的 | 预先铺开的 |

**范围(v0)**:纯前端外壳层改动;零后端契约变化;Workbench 逐像素保留(仅顶栏加切换按钮)。**不做**:主题系统、移动端、跨设备同步、把市场/终端迁入 Focus(边界详见 [Feature SDD §2](../sdd/feats/01-dual-mode-shell/README.md))。

**不变量**:
- **单一 store**——两模式是同一状态的两种视图,切换不丢对话/当前图/测量/草稿,不发请求。
- **Focus ≠ 纯聊天**——点选/圈画修正与"低风险试一把"核对是 B 刚需(需求清单 §2/§3.2),舞台不可省。
- **反长回规则**——新能力默认 Workbench 独占,进 Focus 需显式设计(否则 Focus 三个月后长回一个 IDE)。

## 1. 为什么参照 Codex(设计原则)

Codex(及同类:Claude Code web、Devin)界面成立的原因不是"简洁",而是三条可迁移的原则:

1. **意图入口唯一且显眼**:空状态就是一个输入框。用户不需要先理解界面分区,只需要会说话。对应 Glaux:B 的第一动作是描述研究目标,不是找"资源管理器"。
2. **工作产物按需浮现**:diff/日志在任务卡片里展开,不是常驻面板。对应 Glaux:分割叠加、度量数字在任务卡片 + 舞台中出现,做完即可收起。
3. **过程可解释但不强迫围观**:执行细节折叠在卡片内,信任靠"随时可展开"而非"始终全显示"。对应 Glaux 的验证哲学:信任 = 透明 + 可复现,而不是让 B 盯着所有中间面板。

**刻意不抄的**:Codex 是异步任务农场(提交后走开),Glaux 的 B 场景是同步核对回路(跑一小批 → 十分钟点选核对 → 建立信任),所以 Focus 的舞台是一等公民,而 Codex 没有对应物。

## 2. 信息架构

### 2.1 Focus 模式布局

```mermaid
flowchart LR
    subgraph Focus 模式
        direction LR
        S["会话列表<br/>(窄栏,可收起)<br/>复用 SessionDrawer"]
        C["对话流(主体,居中 ≤720px)<br/>消息 + taskrun 任务卡片<br/>底部 Composer"]
        V["图像舞台<br/>(有活动图/结果时展开)<br/>复用 Viewer + 修正工具"]
        S --- C --- V
    end
    T["顶栏:Glaux 标识 · 图像上下文 · ⚙ 设置 · ⇄ 模式切换"] -.覆盖.- Focus 模式
```

三区职责:

- **会话列表**:复用 feats/00 的 SessionDrawer;默认收起为窄条,悬停/点击展开。
- **对话流**:复用 AgentConversation + ConversationComposer;空状态为居中输入框 + 3~4 张示例任务卡(见 §3.1);`taskrun` 卡片内嵌度量摘要,点击卡片 → 舞台高亮对应叠加。
- **图像舞台**:复用现有 Viewer / VolumeViewer / WsiViewer;仅在有活动图或结果时展开;顶部一条极简工具条(光标/点选修正/圈画/重置——现有 Tool 集子集);可整体收起回到纯对话。

### 2.2 被移除能力的去向(Focus 侧)

| Workbench 能力 | Focus 去向 |
| --- | --- |
| 活动栏 + 资源管理器 | 顶栏轻量图像上下文选择器(待确认 Q2)+ 对话内选图 |
| 插件市场 | 不进 Focus;需要时切 Workbench |
| 底部面板(度量表/输出/终端) | 度量 → 任务卡片 + 舞台叠加;输出/终端不进 Focus |
| StatusBar(坐标/单位/来源) | 移除;坐标类信息移入舞台角落(待确认 Q3) |
| VLM 连接配置入口 | 顶栏 ⚙ 弹层(复用 ConnectionConfig) |
| dockview 拖拽布局 | 不提供;Focus 布局固定(会话栏/舞台仅开合) |

### 2.3 切换

- 位置:两模式顶栏右侧,`⇄ 工作台` / `⇄ 专注`(文案待 i18n)。
- 语义:纯视图切换;同一 zustand store,无数据搬运,无网络请求;`uiMode` 持久化到 localStorage,刷新保持。
- 默认:无持久化键 → Focus(新用户、清空存储者、以及——建议——老用户,待确认 Q4)。
- Workbench 的 dockview 布局键(`glaux.layout.v1`)与 Focus 互不读写,往返切换布局无损。

## 3. 关键界面

> 高保真见[可交互设计稿](../sdd/feats/01-dual-mode-shell/mockup.html);此处只冻结要点。

### 3.1 Focus 空状态(第一眼)

- 居中:产品标识 + 一句价值主张("描述你的研究目标,把图像变成可验证的洞察")。
- 大输入框(即 Composer,居中放大态);下方 3~4 张示例任务卡,点击即填入输入框——示例即教学,替代所有 onboarding 文档。
- 无任何面板、无侧栏、无状态栏。后端未起/无数据集时示例卡置灰并提示,输入框仍可见(沿用"不阻塞外壳"约定)。

### 3.2 Focus 结果态

- 对话流左移让位,舞台自右展开(约 45% 宽);任务卡片显示度量摘要 + 置信/存疑标注,与舞台叠加联动。
- 修正手势直接在舞台可用;修正后来源标记 `human`(沿用现有 source 语义)。

### 3.3 Workbench

- 与现状逐像素一致;唯一改动是 TitleBar 右侧新增切换按钮。

## 4. 用户故事

- **US-1**:B 首次打开 Glaux,看到的是一个输入框和几个例子,而不是 IDE;照着例子跑通第一次分割 + 测量,全程没接触"面板"概念。
- **US-2**:B 跑完一小批后,在舞台上逐张点选核对存疑项,建立"它说有把握的确实对"的信任(需求清单 §2 的信任第一步,在 Focus 内闭环)。
- **US-3**:计算影像专家/内部开发者一键切到 Workbench,获得全量视图(市场、底部面板、终端、拖拽布局),再切回来,B 的对话与结果原样都在。
- **US-4**:任何用户刷新页面,回到离开时的模式与状态。

## 5. 风险与对策

| 风险 | 对策 |
| --- | --- |
| Focus 逐渐长回 IDE(每个新功能都想"顺便"进 Focus) | 反长回规则写入 Feature SDD §7 作为硬约束:默认 Workbench 独占,进 Focus 是显式设计决策 |
| 双模式 = 双倍 UI 维护面 | Focus 全部由现有组件组合而成(仅新增布局壳);组件语义不分叉,分叉只在布局层 |
| B 在 Focus 里缺某能力被卡住 | 切换按钮常驻可见;Focus 空态文案提示"完整工具在工作台模式" |
| 切换语义含糊导致状态 bug | Feature SDD §15 验收清单逐项锁死(往返无损、零请求、布局互不污染) |
