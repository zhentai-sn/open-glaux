# Glaux 标识重做 · 纸面方案

> 承接：[品牌皮肤与小鸮吉祥物](../designs/2026-10-21-001-brand-skin-and-mascot.zh-CN.md)（2026-10-21）。本文只改**标识层**，不改 §3 的配色与形状 token。
> 上位约束：[前端视觉交互设计纲领](frontend-design-charter.zh-CN.md) G5、G9、G10、G11、G12。
> 状态：draft。本文不含任何实现与资产改动，供评审选路线。

## 1 现状与判断

标识的唯一实现是 `frontend/src/components/OwlLogo.tsx`：32 网格内联矢量矩形，3 色，五层细节——面盘 1px 浅色描边、上下两枚深色瞳孔、眼高光、浅色肚皮、两只深色脚。使用点共 5 处：

| 位置 | 尺寸 |
| --- | --- |
| `TitleBar` | 18px |
| `FocusTopBar` | 18px |
| `AgentConversation` 智能体消息徽标 | 18px |
| `FocusShell` 空状态 hero | 40px |
| 应用图标 / `glaux.ico` / favicon | 16–256px，由 64 网格像素清理版导出 |

判断：

1. **主战场在最难的尺寸。** 5 处使用里 4 处是 16–18px，而现状把整只小鸮（含肚皮、脚、高光）放在 18px 里兑现。32 网格缩到 16px 时每个单元只有半个像素，描边与高光必然丢失——2026-10-24 用最近邻降采样并排验证过，16px 下只剩一团紫色与两个点。
2. **标识与吉祥物没有分工。** 标识要极简、单色可用、可注册；吉祥物要表情与姿态。现状是同一份 32 网格同时承担两者，结果两边的约束互相压制。
3. **两套视觉语言并行。** 功能图标是 lucide 线性（SDD 06 D-1：stroke 1.6、currentColor），品牌标识是硬像素，两者在 `TitleBar` 同一行相邻出现。
4. **"复杂"的来源不是细节数量，而是每一层细节都要求小尺寸兑现。** 兑现不了就该在网格里删掉，而不是留在矢量里等大尺寸才好看。

## 2 方法（外部规则）

选型依据是两个已公开的 logo 技能，本方案按它们的规则组织，不照搬其产出：

| 规则 | 出处 | 对本项目的含义 |
| --- | --- | --- |
| 最多 1–2 个核心元素；留白 ≥40–50%；线宽统一；单一焦点；每个元素必须证明存在的理由 | [op7418/logo-generator-skill](https://github.com/op7418/logo-generator-skill) 设计原则 | 18px 的标识只允许 2 个元素 |
| 默认不画整只吉祥物：提取 1–2 个最有辨识度的特征，压成剪影或负形，并写明省略了什么 | [SanbaoAI/mascot-logo-generator](https://raw.githubusercontent.com/SanbaoAI/logo-generator-skill/main/skills/mascot-logo-generator/prompt.md) | 猫头鹰的可提取特征：双眼之间的竖向隔断、喙、耳羽、侧身轮廓 |
| 评审载体是品牌系统展示板（主标 / favicon / seal / lockup / 黑白 / 压印 / 符号释义），不是白底居中一张图 | [SanbaoAI/logo-generator-skill](https://github.com/SanbaoAI/logo-generator-skill/blob/main/README.zh-CN.md) | 验收要并排看 16 / 24 / 32 / 48 / 256、单色、反白、seal |
| 先发散 6+ 变体再收敛；标记必须是 SVG | op7418 工作流 | 先出 4 条特征路线，再定 1 条主线 |
| 不用整身姿态、不依赖只有大尺寸才成立的细节、必须单色可用 | SanbaoAI `prompt.md` 的 Avoid 列表 | 肚皮、脚、眼高光、1px 面盘描边应当删除 |

## 3 品牌 brief（后续所有方案对照此节）

| 项 | 内容 |
| --- | --- |
| 名称与词源 | Glaux = γλαύξ，雅典娜的猫头鹰。语义指向观察、夜视、辨识 |
| 定位 | AI 原生影像分析：自然语言进、结构化产物出；研究用途，不做生产级临床诊断 |
| 受众 | 非计算研究者（B）为主，专家与开发者为次 |
| 性格 | 秩序、可信、可复现。不是消费级萌物 |
| 使用面 | 16–18px 顶栏、32–64 favicon、96–256 安装器与门户、单色印刷、IDE 内嵌 |
| 硬约束 | 强调紫只表达可交互，语义色不参与品牌化（G5）；标识不依赖颜色区分（G10）；不承载文案，不引入新 i18n 键（G9） |
| 已有资产 | 无字标字体资产，lockup 目前 = 图标 + 纯文本 `Glaux` |

## 4 特征路线

四条路线都只描述"取什么、夸什么、省什么"，不预设画法。

### R1 · 双眼与喙（负形）

- 取：面盘被竖向隔断分成两半、喙从隔断下缘伸出的结构。
- 夸：竖向隔断的宽度与两眼间距的比例，让它成为骨架。
- 省：耳羽、肚皮、脚、高光、面盘轮廓线。
- 16px 预期：两眼为实心块、隔断为 1 单元，可辨。
- 风险：与通用"猫头鹰脸"图标接近，需要靠比例与负形产生区分度。

### R2 · 耳羽剪影

- 取：头顶两撮耳羽构成的 V 形轮廓。
- 夸：两撮耳羽的夹角与间距。
- 省：眼、喙、身体。
- 16px 预期：可辨为标记，但语义脱离猫头鹰，识别依赖品牌名。
- 风险：抽象后与"山峰""M""∧"等符号撞车。

### R3 · 侧身站姿（钱币式）

- 取：雅典猫头鹰钱币的侧身站立轮廓——头正面、身侧向、尾短、双足并立。
- 夸：站姿的整块剪影，两眼挖空为负形。
- 省：月桂与橄榄枝、羽毛分块、爪的细节。
- 16px 预期：整块剪影可辨，眼为负形点。
- 风险：小尺寸下剪影必须极简，否则退化；但它是四条里与竞品区分度最高、词源绑定最强的一条。

### R4 · 字标优先

- 取：`GLAUX` 全大写窄体的字标，`O` 内嵌双眼或耳羽。
- 省：独立标记。
- 16px 预期：favicon 退化为字母 `G` 或 `O`。
- 风险：需要先有字标字体资产（当前没有），且与"图标 + 文本"现有的两处 lockup 重复。

### 收敛建议

**R1 作标识主线，R3 作二级徽记。**

- R1 满足 1–2 元素、单色可用、16px 可兑现，且可以同时出线性版本与 lucide 同构（同一几何，线性版只在 ≥24px 用）。
- R3 只在 ≥48px 兑现，正好落在吉祥物与展示位（启动画面、安装器、门户、周边），不进 favicon，避免与 R1 抢主战场。
- R2、R4 记为备选，本轮不并行推进。

## 5 标识系统规格

只写契约，不出图。

| 项 | 规格 |
| --- | --- |
| 网格 | 标识用 **16 网格主稿**（另画，不是 32 网格缩图）；24 / 32 / 48 用整像素倍率放大；吉祥物继续用 32 网格 |
| 颜色 | 2 色：品牌紫 `#7C4DD6` + 纸底 `#F0EAFC`。单色版一色 + 负形；反白版紫底纸色图形 |
| 细节预算 | 16–18px：至多 3 个形状（两眼 + 喙或耳羽）；32px 起允许第 4 层；72px 起允许面盘轮廓 |
| 最小尺寸 | 16px；低于 16px 不提供逐像素版本，用 16 网格主稿缩放并接受模糊 |
| 清晰空间 | 四边 ≥ 图形高度的 1/4 |
| 与功能图标的关系 | 标识只出现在品牌位（顶栏、应用图标、门户、安装器）；功能图标继续 lucide；品牌标识不与 lucide 图标在同一视觉行混排——`TitleBar` 与 `FocusTopBar` 现状需复查 |
| 交付物 | SVG（手写、非图像模型生成）、ICO 16–256 七档、favicon、单色、反白、seal（圆形徽记）、lockup（标识 + 字标） |

## 6 吉祥物

保持不变：32 网格、10 态、sprite strip、`prefers-reduced-motion` 退化。新增一条分工约束——**吉祥物只在 ≥48px 出现**，小尺寸位置改用标识，避免同一屏出现两种不同精度的同一形象。

## 7 验收清单

1. 16 / 24 / 32 / 48 / 256 五档并排，最近邻缩放后仍可辨认（人工走查，留走查记录）
2. 单色黑、单色白、反白三版不丢形状
3. favicon、seal、lockup 由同一主稿导出，形状同源
4. 不使用通用猫头鹰剪贴画轮廓，不与已知商标轮廓重合
5. 品牌标识与 lucide 图标不在同一视觉行混排
6. `prefers-reduced-motion` 下吉祥物仅静止帧
7. 标识不承载文案，不新增 i18n 键
8. 设计示意图在落地页与文档中标注为示意，不冒充成品（G6）

## 8 影响面（仅列出，本轮不改）

| 目标 | 变化 |
| --- | --- |
| `frontend/src/components/OwlLogo.tsx` | 由 32 网格五层细节改为 16 网格主稿；API 不变（`size`） |
| `launcher/windows/glaux.svg`、`.ico`、`build-icon.py` | 改用新主稿导出；保留"品牌成品优先"分支 |
| `docs/landing` 品牌区、安装器窗口 | 换用新图标与徽记 |
| 2026-10-21 品牌皮肤设计 §4.1 | 造型契约需修订（网格 32 → 标识 16 主稿 + 吉祥物 32） |
| 若采纳 R3 徽记 | 新增启动画面与安装器徽记位，需先确认产品是否存在该界面 |

## 9 未决

1. 路线是否按 **R1 主线 + R3 二级徽记** 收敛。
2. 输入框上沿的小鸮（`Mascot` 的 48px 位置）改为标识还是保留缩小版吉祥物——这决定 §6 的 ≥48px 约束是否成立。
3. 像素风是否只保留在吉祥物层，标识改线性；还是标识也保留像素网格。
4. 是否做 seal 与压印：产品当前没有印刷面，可能不需要。
5. 字标是否立项（当前只有纯文本 `Glaux`）。
