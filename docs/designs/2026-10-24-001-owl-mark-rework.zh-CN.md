# Glaux 标识重做 · 纸面方案

> 承接：[品牌皮肤与小鸮吉祥物](2026-10-21-001-brand-skin-and-mascot.zh-CN.md)（2026-10-21）。本文只改**标识层**，不改 §3 的配色与形状 token。
> 上位约束：[前端视觉交互设计纲领](frontend-design-charter.zh-CN.md) G5、G9、G10、G11、G12。
> 状态：已实施（2026-10-24）。§1–§4 是选题过程，§5 起是定稿契约与改动记录。

## 1 现状与判断

标识的唯一实现是 `frontend/src/components/OwlLogo.tsx`：32 网格内联矢量矩形，3 色，五层细节——面盘 1px 浅色描边、上下两枚深色瞳孔、眼高光、浅色肚皮、两只深色脚。使用点共 5 处：

| 位置 | 尺寸 |
| --- | --- |
| `TitleBar` | 18px |
| `FocusTopBar` | 18px |
| `AgentConversation` 智能体消息徽标 | 18px |
| `FocusShell` 空状态 hero | 40px |
| 应用图标 / `glaux.ico` / favicon | 16–256px，由 64 网格像素清理版导出 |

判断：

1. **主战场在最难的尺寸。** 5 处使用里 4 处是 16–18px，而现状把整只小鸮（含肚皮、脚、高光）放在 18px 里兑现。32 网格缩到 16px 时每个单元只有半个像素，描边与高光必然丢失——2026-10-24 用最近邻降采样并排验证过，16px 下只剩一团紫色与两个点。
2. **标识与吉祥物没有分工。** 标识要极简、单色可用、可注册；吉祥物要表情与姿态。现状是同一份 32 网格同时承担两者，结果两边的约束互相压制。
3. **两套视觉语言并行。** 功能图标是 lucide 线性（SDD 06 D-1：stroke 1.6、currentColor），品牌标识是硬像素，两者在 `TitleBar` 同一行相邻出现。
4. **"复杂"的来源不是细节数量，而是每一层细节都要求小尺寸兑现。** 兑现不了就该在网格里删掉，而不是留在矢量里等大尺寸才好看。

## 2 方法（外部规则）

选型依据是两个已公开的 logo 技能，本方案按它们的规则组织，不照搬其产出：

| 规则 | 出处 | 对本项目的含义 |
| --- | --- | --- |
| 最多 1–2 个核心元素；留白 ≥40–50%；线宽统一；单一焦点；每个元素必须证明存在的理由 | [op7418/logo-generator-skill](https://github.com/op7418/logo-generator-skill) 设计原则 | 18px 的标识只允许 2 个元素 |
| 默认不画整只吉祥物：提取 1–2 个最有辨识度的特征，压成剪影或负形，并写明省略了什么 | [SanbaoAI/mascot-logo-generator](https://raw.githubusercontent.com/SanbaoAI/logo-generator-skill/main/skills/mascot-logo-generator/prompt.md) | 猫头鹰的可提取特征：双眼之间的竖向隔断、喙、耳羽、侧身轮廓 |
| 评审载体是品牌系统展示板（主标 / favicon / seal / lockup / 黑白 / 压印 / 符号释义），不是白底居中一张图 | [SanbaoAI/logo-generator-skill](https://github.com/SanbaoAI/logo-generator-skill/blob/main/README.zh-CN.md) | 验收要并排看 16 / 24 / 32 / 48 / 256、单色、反白、seal |
| 先发散 6+ 变体再收敛；标记必须是 SVG | op7418 工作流 | 先出 4 条特征路线，再定 1 条主线 |
| 不用整身姿态、不依赖只有大尺寸才成立的细节、必须单色可用 | SanbaoAI `prompt.md` 的 Avoid 列表 | 肚皮、脚、眼高光、1px 面盘描边应当删除 |

## 4 特征路线

四条路线都只描述"取什么、夸什么、省什么"，不预设画法。

### R1 · 双眼与喙（负形）

- 取：面盘被竖向隔断分成两半、喙从隔断下缘伸出的结构。
- 夸：竖向隔断的宽度与两眼间距的比例，让它成为骨架。
- 省：耳羽、肚皮、脚、高光、面盘轮廓线。
- 16px 预期：两眼为实心块、隔断为 1 单元，可辨。
- 风险：与通用"猫头鹰脸"图标接近，需要靠比例与负形产生区分度。

### R2 · 耳羽剪影

- 取：头顶两撮耳羽构成的 V 形轮廓。
- 夸：两撮耳羽的夹角与间距。
- 省：眼、喙、身体。
- 16px 预期：可辨为标记，但语义脱离猫头鹰，识别依赖品牌名。
- 风险：抽象后与"山峰""M""∧"等符号撞车。

### R3 · 侧身站姿（钱币式）

- 取：雅典猫头鹰钱币的侧身站立轮廓——头正面、身侧向、尾短、双足并立。
- 夸：站姿的整块剪影，两眼挖空为负形。
- 省：月桂与橄榄枝、羽毛分块、爪的细节。
- 16px 预期：整块剪影可辨，眼为负形点。
- 风险：小尺寸下剪影必须极简，否则退化；但它是四条里与竞品区分度最高、词源绑定最强的一条。

### R4 · 字标优先

- 取：`GLAUX` 全大写窄体的字标，`O` 内嵌双眼或耳羽。
- 省：独立标记。
- 16px 预期：favicon 退化为字母 `G` 或 `O`。
- 风险：需要先有字标字体资产（当前没有），且与"图标 + 文本"现有的两处 lockup 重复。

### 收敛建议

**R1 作标识主线，R3 作二级徽记。**

- R1 满足 1–2 元素、单色可用、16px 可兑现，且可以同时出线性版本与 lucide 同构（同一几何，线性版只在 ≥24px 用）。
- R3 只在 ≥48px 兑现，正好落在吉祥物与展示位（启动画面、安装器、门户、周边），不进 favicon，避免与 R1 抢主战场。
- R2、R4 记为备选，本轮不并行推进。

可视化评审页：[assets/2026-10-24-owl-mark-rework/routes.html](assets/2026-10-24-owl-mark-rework/routes.html)。同一套几何按 16 / 24 / 32 / 48 / 96 / 256 逐级渲染，每条路线并排给出单色版、反白版与 18px 顶栏上下文。页面里的几何是程序化草图，不是最终美术稿。

## 5 标识系统规格

已按 2026-10-24 选定的「A 浅缺口」定稿。主稿唯一来源是 `frontend/src/components/OwlLogo.tsx`，其余资产从它解析生成。

| 项 | 规格 |
| --- | --- |
| 网格 | 16 × 16，所有形状落在整格；吉祥物继续用 32 网格 |
| 面盘 | 椭圆，中心 `(8, 9.4)`，半径 `6.0 × 5.5` |
| 耳羽 | 头顶中央 V 形缺口：上口 `y=3.2`、尖底 `y=6.4`、半宽 `2.4`（宽 4.8、深 3.2）；缺口两侧各留一个圆丘，无外凸尖角 |
| 眼 | 两只负形眼，中心 `(5, 9.2)` 与 `(11, 9.2)`，半径 `1.9`；行宽 `2 / 4 / 4 / 2`，两眼隔断 2 单元 |
| 底部 | 逐行收口 `12 / 10 / 8 / 4`，不单独画喙 |
| 颜色 | 面盘 `#7C4DD6`、眼 `#F0EAFC`；不使用第三种颜色 |
| 尺寸 | 只取 16 的整数倍：16 / 32 / 48。代码中原有的 18 与 40 已改为 16 与 48——非整数倍时单元格宽度不是整像素，硬边会歪斜 |
| 图标形态 | 纸色圆角板（`#F0EAFC`，圆角 3.2 单元）+ 同一份紫色小鸮；造型不变，只加底板，使图标在浅色与深色任务栏上都成立 |
| 清晰空间 | 四边 ≥ 图形高度的 1/4 |
| 与功能图标的关系 | 标识只出现在品牌位（顶栏、应用图标、门户、安装器）；功能图标继续 lucide；两者不在同一视觉行混排 |
| 交付物 | `OwlLogo.tsx`（唯一主稿）、`build-icon.py` 导出的 `launcher/windows/glaux.svg`、`.png`（256）、`.ico`（16/32/48/64/128/256）、`frontend/public/favicon.png`（32）、`icon-512.png` |

## 6 吉祥物

2026-10-24 按标识的新造型重画（维护者选 B 方案）：**只做头**——心形面盘 + 头顶 V 形缺口 + 浅色眼盘，不画身体与双足，抽象程度与标识一致，多出来的只有表情。帧数与时序沿用 `MASCOT_TRACKS`，`Mascot.tsx` 与 `mascot.css` 未改。

| 项 | 规格 |
| --- | --- |
| 网格 | 32 × 32，每状态一条 8 列条带；显示 64px（32 网格 2×，整像素，`image-rendering: pixelated`） |
| 面盘 | 椭圆，中心 `(16, 16)`，半径 `10.8 × 10.4`；不含身体与双足 |
| 耳羽 | 头顶中央 V 形缺口：上口 `y=4.6`、尖底 `y=11.0`、半宽 3.0（宽 6.0、深 6.4） |
| 眼 | 浅色眼盘 7 × 7，中心 `(11.3, 17.2)` 与 `(20.7, 17.2)`；瞳 3 × 3 居中 |
| 喙 | 眼下深色小三角，自 `y=21` 起；`open` 多一行，`flat` 为一条横线（报错态） |
| 颜色 | 面盘 `#7C4DD6`、眼盘 `#F0EAFC`、瞳/喙 `#2A1B4A` |
| 状态 | idle 4 / blink 2 / thinking 4 / typing 4 / happy 4 / error 3 / notification 3 / sleeping 2 / waking 3 / poke 2 |
| 配件 | 见下表；只占头部四周留白，同三色、无描边，不参与呼吸位移 |
| 表情纪律 | 十态共用同一张眼盘与同一副轮廓，只改眼盘内的瞳、眼睑与嘴——保证切换状态时形状不跳 |
| 生成 | `scripts/release/build-mascot.py`（Pillow 程序化绘制，`--preview` 出对照图）；改造型只改这一个脚本 |

### 6.1 各状态配件

| 状态 | 配件 | 说明 |
| --- | --- | --- |
| idle / blink | 无 | 保持干净，只靠呼吸与眨眼 |
| thinking | 三颗点绕圈 | 4 帧转 90°，点沿头部右上的小圆周走 |
| typing | 头戴式耳机 | 沿头顶弧形的头梁 + 两侧耳罩，表示沉浸输出 |
| happy | 两颗四角星 | 一大一小，分列左上与右上 |
| error | 感叹号 | 头部右上，配 × 眼与横嘴 |
| notification | 问号 | 等待用户确认 |
| sleeping | 两个 z | 一大一小，交替漂移 |
| waking | 无 | 眼睑由半开转全开，不加配件 |
| poke | 左右动势线 | 三对短斜线，随身体左右摆 |

分工约束沿用——**吉祥物只在 ≥48px 出现**，小尺寸位置用标识。

十态对照图（每帧 3×）：[mascot-states.png](assets/2026-10-24-owl-mark-rework/mascot-states.png)。

## 7 验收结果

| 项 | 结果 |
| --- | --- |
| 16 / 32 / 48 / 256 走查 | 通过。16px 下两只眼与顶部缺口都可辨；对照页见 [heart.html](assets/2026-10-24-owl-mark-rework/heart.html)，实机走查在 `FocusTopBar`（16px）与空状态 hero（48px） |

| 深色底可读 | 通过。图标形态为纸色底板 + 紫色小鸮，深色任务栏上仍可辨 |
| 单色版 | 本轮不交付：产品没有单色印刷面；需要时按 §5 把眼洞视作负形、面盘用单色重填即可 |
| lucide 混排 | 通过。品牌位与功能图标不在同一行（顶栏只有标识、字标、模式按钮） |
| 文案与 i18n | 通过。标识无文字，未新增 i18n 键 |
| 吉祥物 | 条带契约不变（256×32、8 列，48px 下 `background-size: 384px 48px`）；形状与标识同源，只有头，不含身体与足。3× 与 48px 预览见 §6 的对照图 |
