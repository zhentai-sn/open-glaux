# Glaux 品牌皮肤与小鸮吉祥物 · 设计

> 承接需求：界面改为 Claude 式暖纸风格并更灵动；品牌角色使用小鸮；覆盖前端全界面、安装器、门户与资产。
> 上位约束：[前端视觉交互设计纲领](frontend-design-charter.zh-CN.md)。本设计**修订 G11 的缺省主题立场**（深色冷调 → 暖色浅色为默认，影像视口例外），其余原则不变。

## 1 背景

现有视觉立场是"科学仪器的秩序之美"：深色冷调、色彩即语义、零装饰色、4/6/8px 圆角、动效只解释因果。用户要求改为 Claude 式暖纸基底、更灵动，并引入以小鸮为原型的品牌角色。

本次改动**不动验证器与语义纪律**（G5 三态守卫、来源徽标、语义色与交互色分离），只换视觉基底与节奏，因此风险集中在"看起来像另一个产品"，而不是"读数不可信"。

## 2 范围

| 覆盖 | 内容 |
| --- | --- |
| 前端全界面 | Focus（对话）与 Workbench（工作台）的 chrome、卡片、输入区、设置页 |
| 吉祥物 | 输入框上沿的像素小鸮，随智能体状态换帧（新增） |
| 桌面外壳 | 安装器与控制窗口的配色与图标 |
| 门户 | `docs/landing` 的配色与品牌区 |
| 品牌资产 | 应用图标 / ICO / README 视觉 |

不在范围：可拖拽桌宠（亲密度、喂食、气泡栈）、Live2D、像素化图标体系、皮肤切换机制。

## 3 视觉体系

### 3.1 配色

暖纸基底 + 品牌紫单强调。Token 名不变，只换值，组件改造面因此可控。

| Token | 亮色值 | 用途 |
| --- | --- | --- |
| `--editor` | `#FCFCFB` | 画布 / 对话底 |
| `--sidebar` | `#FAF9F5` | 侧栏 / 二级面 |
| `--activity` | `#F7F5EF` | 活动栏 / 分区底 |
| `--line` / `--line2` | `#E8E6DC` / `#DEDCD2` | 发丝线 / 强描边 |
| `--ink` / `--mid` / `--faint` | `#141413` / `#6E6A60` / `#A6A094` | 文本三级明度 |
| `--accent` | `#7C4DD6` | 唯一交互强调（按钮、链接、选中、焦点环） |
| `--agent` | `#7C4DD6` | 智能体紫（与强调同源，可由用户覆盖，SDD 12） |
| `--good` / `--warn` / `--crit` | `#1E8C55` / `#B7791F` / `#D64545` | 置信语义，永不参与装饰 |
| `--stage` | `#1C1B19` | 影像舞台（两档主题下恒定） |

规则沿用纲领 G5 与 G11 的硬约束：不出现纯白纯黑、不用冷灰、强调色占比 <10%、语义色与交互色不混用。

### 3.2 排版

- 正文仍 `13px / 12px / 11px` 三档，行高提到 `1.6`
- **标题引入衬线**（对话标题、空状态 hero、设置分区标题），正文与数值保持无衬线 + `tabular-nums`
- 衬线字体未决，见 §9

### 3.3 形状与层级

- 圆角阶上调：`--radius-sm` 6px、`--radius-md` 10px、`--radius-lg` 14px
- 层级靠明度与留白，仍不堆叠阴影；仅在浮层（弹窗、菜单）允许一层柔阴影
- 分隔线降到 `#E8E6DC` 一类暖灰，弱于现状

### 3.4 动效

| 场景 | 时长 | 曲线 |
| --- | --- | --- |
| 微交互（按压、hover） | 120–160ms | `ease-out` |
| 卡片 / 面板入场 | 200–280ms | `cubic-bezier(0.34, 1.4, 0.64, 1)`（轻微过冲） |
| 模式切换 | ≤320ms | crossfade，不做翻转 |
| 吉祥物逐帧 | 100–180ms/帧 | 线性 |

保留 G12 的判定标准：动效只解释"什么变了、从哪来、到哪去"；不引入装饰性循环动画。

## 4 小鸮吉祥物

### 4.1 造型契约

| 项 | 规格 |
| --- | --- |
| 造型 | 几何与 `launcher/windows/glaux.svg` 同源（同一套 32 网格像素），但**背景透明**：对话框上只浮着小鸮本身，不带紫底方块 |
| 网格 | 32×32 像素，整像素放大（48px = 1.5x），禁止插值 |
| 特征 | 两个大圆眼 + 浅色面盘 + 小三角喙 + 头顶两撮短耳羽 + 紧凑圆身 |
| 配色 | 身体 `#7C4DD6`、面盘 `#F0EAFC`、瞳孔 `#2A1B4A` |
| 锚点 | 底部中心，贴输入框上沿；每态带裁剪框 `box`，切换不跳位 |
| 尺寸 | 32 / 48 / 72px 三档 |
| 32px 可读性 | 只保留"两眼 + 耳羽 + 喙"，其余细节舍弃 |

### 4.2 状态机

| 状态 | 帧数 | 帧时长 | 触发 |
| --- | --- | --- | --- |
| idle | 4 | 110ms | 默认，呼吸（身体上下 1px） |
| blink | 2 | 120ms | idle 中随机 8–15s 插入 |
| thinking | 4 | 180ms | 模型思考 |
| typing | 4 | 100ms | 流式输出 / 调工具 |
| happy | 4 | 120ms | 任务完成 |
| error | 3 | 150ms | 任务失败 |
| notification | 3 | 200ms | 等待用户确认（审批卡片） |
| sleeping | 2 | 1200ms | 长时间无操作 |
| waking | 3 | 120ms | 点击唤醒 |
| poke | 2 | 100ms | 点击反应（左/右） |

### 4.3 运行时实现

沿用 CSS sprite strip 契约（8 列一条 strip）：

- 每状态一根 strip，按 `background-position` 逐帧，`setTimeout` 驱动（不用 rAF，避免后台节流下跳帧）
- 每状态声明 `frames`、`box`（裁剪框）、`still`（静止帧）
- 状态来源复用既有会话事件：`turn.start` / `tool.call` / `tool.end` / `turn.end` / 交互请求挂起
- 无会话活动超过 N 分钟进入 `sleeping`，任意交互进入 `waking`

### 4.4 可访问性

- `prefers-reduced-motion` 下关闭呼吸与眨眼循环，仅保留状态切换
- 吉祥物 `aria-hidden`，状态语义仍由既有状态栏与对话区承担
- 点击反应不承担任何功能，不拦截输入框焦点

## 5 例外与保留

1. **影像舞台保持深色**：`[data-viewer-surface]` 子树重声明深色值，两种主题下都不变（SDD 12 既有机制）
2. **品牌标识统一为像素小鸮**：`OwlLogo.tsx` 已改为内联矢量矩形（32 网格、3 色、`shapeRendering="crispEdges"`），18px 与 40px 下都保持像素硬边；`build-icon.py` 增加"品牌成品优先"分支，OwlLogo 不再承担图标生成源的职责
3. **语义色与交互色分离**：`good/warn/crit` 不参与品牌化

### 7.2 吉祥物动画帧（待产出）

按 32px 网格逐帧绘制，每态 2–4 帧，共 10 态；以上图标作为造型基准。

### 7.3 门户配图

复用应用界面截图 + 新配色，输出 webp。

图像模型只负责图标资产的设计感；动画帧必须按网格重绘——AI 输出的像素图边缘不对齐网格，不能直接做 sprite 帧。

## 8 验收

1. 默认主题为暖纸浅色；影像舞台在两种主题下仍为深色
2. `rgba(0,0,0`、`#000`、冷灰一类硬编码颜色在 `frontend/src` 内清零
3. 强调色仅出现在可交互元素上；语义色仅出现在置信、澄清、拒绝三态
4. 吉祥物 10 态齐备，切换不跳位；32px 下可辨认
5. `prefers-reduced-motion` 下无循环动画，功能语义完整
6. 正文 13px、数值 `tabular-nums`、单位伴随数值
7. 双语文案无硬编码，全部走 i18n 键（G9）
8. 键盘可达性与可见焦点环不退化（G10）

## 9 未决

1. **中文衬线字体**：跨平台可靠的中文衬线需打包字体文件（思源宋体子集体积大）；备选是仅在拉丁标题启用衬线、中文回落到黑体
2. **深色主题去留**：本次只改浅色基底；深色是否保留、是否改为"暖夜"另行决定
3. **组件覆盖面**：20–30 个组件需逐个核对硬编码值，实际数量以扫描结果为准
