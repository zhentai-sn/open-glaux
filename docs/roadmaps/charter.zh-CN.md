# Glaux 纲领 · Charter

> **用途**：阶段一的交付物，也是 Glaux 一切决策的组织原则——产品、需求、架构、路线图都从这里派生。
> **日期**：2026-07-05 · **状态**：v1（奠基）
> **一句话**：推理正在商品化；我们建的是生物医学影像洞察赖以发生的**环境**。

## 一、核心信念

通用智能体（Claude、Codex…）的推理与规划能力会持续变强、并被商品化。**真正 durable、且通用智能体顾不到的，是"生物医学影像洞察赖以发生的环境"——平台、底座。** 只有在 Glaux 这套环境里，智能体才能真正发挥能力、完成用户的目标：生物医学影像洞察。

## 二、Glaux 是什么（身份）

**Glaux 首先是一个环境 / 底座，而不是一个智能体。**

> 通用智能体是**大脑 / 引擎**（自带、可配置、正在商品化）；Glaux 是**身体 + 世界**——眼、手、器械、律法、记忆。缸中之脑什么也完不成。价值在具身，在环境。

支撑：
- 智能体本质是 policy；policy 脱离 environment 毫无价值。Glaux 定义智能体能*看到*什么、能*正确地做*什么、以及*怎么算对*。
- 这如同 Claude Code：底层是通用模型，让它对"写代码"有用的是那套 harness（工具、验证回路）。Glaux 是"生物医学影像洞察"的 harness。**模型商品化，harness / 环境才是产品。**
- 模型变强让*大脑*更强，但不会自动给你：正确的模态解码、带物理校准的测量、领域护栏、验证底座、以及累积的领域记忆。**模型进步 ≠ 环境进步**——这是 10 年生存期的根。

## 三、与通用智能体的关系（已拍板）

- **引擎可配置，两者兼有**：用户可自配 API / 模型（BYO，Claude、GPT…），Glaux 同时提供自有参考智能体，兜住 UX 与飞轮入口。
- **谁当引擎不动摇根基**：飞轮与验证长在*环境*里，不在 agent 里。所以"对外开放引擎"从威胁变成**分销**——Claude Code / Codex 从对手变成环境里的租客。
- **留住产品面**：纯 BYO 会把用户关系让给模型厂商，所以 Glaux 必须有自己的产品体验；但护城河始终在环境。

## 四、环境的四层（要建、要守的实体）

| 层 | 隐喻 | 内容 | 通用 agent 缺的正是这个 |
| --- | --- | --- | --- |
| **表征层** | 眼 | 把任意模态解码成统一的可计算表征——智能体*看到*的 | 没有跨模态、正确的视觉输入 |
| **动作层** | 手 + 器械 | 分割 / 测量 / 重建作为一等操作，带单位、尺度、模态语义与护栏——智能体*正确地*做 | 会写代码，但不知道这个模态下什么算对 |
| **验证层** | 律法 + 裁判 | ground-truth、provenance、可重跑、审计轨迹——让输出成为*可信的科学* | 优化"看起来对"，不担保可复现 |
| **记忆层** | 累积的经验 | 已验证轨迹 + 人工校正 + 领域先验——会*复利*的飞轮 | 跑完即忘，不沉淀领域 |

**这四层就是路线图真正要建的东西；`记忆层`（飞轮）是最强、会复利的护城河。**

## 五、发展目标（北极星）

> 成为**生物医学影像洞察的 agent-native 环境**：任何智能体（你的或我们的）跑在其上，就能把任意模态的生物医学图像，变成可验证、可复现的洞察。

## 六、决策过滤器（纲领怎么用）

任何一份工作，动工前问三句：
1. **更强的模型会让它作废吗？** 会 → 负债，最小化投入（薄 wrapper、提示词链、硬编码流程）。
2. **更强的模型会让它更值钱吗？** 会 → 护城河，值得投入（环境四层里的任何一层）。
3. **它加深了四层中的哪一层？** 答不上来 → 大概率是在"让 agent 更聪明"，而那是引擎厂商的活，不是我们的。

- 底线纪律：**环境必须"深"。** 只调个模型返回 mask 的环境，会被 `napari-mcp + 通用 agent` 免费复刻——深度（动作正确性 + 验证 + 校准 + 模态广度 + 飞轮）才是护城河。
- 工程纪律：**复用优先，不重复造轮子。** 任何特性动工前先调研现成依赖：有成熟开源库/组件能承接的（如 `@cornerstonejs/tools` 的标注/分割工具），一律直接引入集成，不手写平行实现；自研只留给四层护城河所在（校准、验证、模态语义、飞轮）与成熟库覆盖不到的领域特化交互（此时也应优先扩展其框架而非另起炉灶）。引入成套平台（交出架构主权的）除外。

## 七、边界（刻意划的）

- 范围：**图像 → 理解 → 表征**。用户拿表征去做决策 / 规划 / 模拟，在 Glaux 之上自建。
- **研究，非临床**：IRB 治理、脱敏数据的回顾性研究在内；受监管的临床诊断（FDA / NMPA）在外。红线：研究洞察，而非临床决策。
- **远期**（超出当前边界）：环境成熟并跨过 SaMD 监管门槛后，方向会从「洞察」延伸到**辅助决策**——见[路线图 · 远景](20260705-product-roadmap.zh-CN.md)。这是远景，不改变近中期"研究非临床"的红线。

## 八、已拍板的决定 · 2026-07-05

- **A. 身份**：Glaux 首先是**环境**；自有智能体只是环境里的参考实现，不是核心资产。
- **B. 引擎立场**：**两者兼有**——用户可自配 API / 模型（BYO），同时提供自有参考智能体。
