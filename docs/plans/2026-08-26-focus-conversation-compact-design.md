# Focus 对话区专业紧凑型设计

## 背景

Focus 模式把消息流、配置状态条和输入框共同限制为 720px 并居中。消息流自身承担滚动，因此滚动条也停在居中正文列右边，视觉上悬在屏幕中部。助手回复沿用了窄侧栏的整块卡片样式；在宽屏 Focus 模式中，背景、边框、较大行距和段落间距叠加后显得松散而厚重。

## 目标

- 将消息流滚动条移动到 Focus 对话区域最右侧。
- 正文继续保持适合阅读的居中限宽，不随滚动层铺满。
- 助手回复改为平铺正文，用户消息保留右对齐气泡。
- 收紧 Markdown 和消息轮次的垂直密度。
- 保持消息协议、状态管理、自动滚动和 Workbench 窄面板行为不变。

## 布局

Focus 模式下，`.conversation-stream` 不再参与 720px 居中限宽，而是铺满整个对话列并承担滚动。它的直接消息子项单独设置最大宽度并居中：

- 宽屏正文最大宽度为 720px。
- 两侧保留安全内边距，窄屏不贴边。
- Composer、配置状态条和错误条仍保持原有居中宽度。
- 滚动条位于完整消息流的右侧边界。

## 消息样式

- 助手消息取消正文卡片的背景、边框、圆角和大块内边距。
- Glaux 标识继续作为角色锚点，不改变消息语义或 DOM 结构。
- 用户消息继续使用右对齐气泡，最大宽度约为正文列的 70%，窄屏放宽到 90%。
- “重新生成”等次要操作降低默认对比度，在当前回复悬停或键盘聚焦时增强。

## 排版

- Focus 助手 Markdown 使用 13px 字号和 1.5 行高。
- 段落上下间距调整为 4px。
- 列表整体间距调整为 4px，列表项间距调整为 2px。
- 标题上下间距收紧，同时保留层级差异。
- 消息轮次间距调整为 11px。
- 代码块、引用块和表格保留现有视觉语义，仅收紧垂直间距。

## 滚动条

- Focus 消息流使用更细的滚动条和透明轨道。
- 静止时降低对比度，悬停时提高滑块亮度。
- Firefox 与 WebKit 分别使用各自支持的滚动条属性。

## 验证

- Focus 模式宽屏下滚动条位于对话列最右侧，正文仍居中且不超过 720px。
- 助手回复无大面积卡片背景，用户气泡仍右对齐。
- Markdown 段落、列表、标题、代码块和引用块保持可读。
- 空状态、自动滚动、图片消息、工具调用卡片和建议卡片不受影响。
- Workbench 模式保留原有窄面板样式。
- 运行 AgentConversation 相关测试、前端 ESLint 和可用的类型检查。
