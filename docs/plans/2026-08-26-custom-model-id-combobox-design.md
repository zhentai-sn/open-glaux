# 自定义模型 ID 组合框设计

## 背景

智能体连接面板在尚未拉取模型时使用文本框，允许手动输入模型 ID；拉取模型成功后则切换为原生 `select`。此时用户只能选择服务端模型列表里的值，无法修正过期 ID，也无法使用兼容端点未列出的模型。

## 目标

- 模型列表存在时仍允许输入任意模型 ID。
- 保留从服务端候选列表快速选择模型的能力。
- 精确选择已知模型时继续同步上下文窗口与最大输出 Token。
- 刷新模型列表时不覆盖用户当前填写的模型 ID。
- 不引入新的前端依赖。

## 方案

使用原生 `input` 与 `datalist` 组成可输入组合框：

- `input` 继续绑定 `connection.model`，用户可以输入任意字符串。
- `datalist` 的候选项来自 `connection.models`。
- 每次模型值变化时，以完整 ID 在候选列表中精确匹配。
- 匹配成功时通过现有 `metaForModel` 同步模型元数据；匹配失败时只更新模型 ID，保留当前元数据供用户调整。
- 拉取模型只更新候选列表；当前 ID 不在新列表时仍原样保留。

原生 `datalist` 不能在候选项内渲染视觉能力图标。模型 ID 的可输入性和浏览器原生键盘交互优先于该辅助标记；视觉能力探测结果仍保留在连接状态中，供运行时使用。

## 数据流

1. 用户点击“拉取模型”，运行时从兼容端点读取模型列表。
2. 连接面板把列表写入 `connection.models`，不改变 `connection.model`。
3. 用户输入或选择模型 ID。
4. 面板立即写入 `connection.model`。
5. 若 ID 与候选项精确匹配，面板同时写入该模型的上下文窗口和最大输出 Token；否则保留现值。

## 测试

- 拉取模型后仍可手动输入列表外的自定义 ID。
- 从候选列表选择模型后更新模型 ID。
- 输入与候选精确匹配的 ID 后同步上游元数据。
- 自定义 ID 不覆盖当前上下文窗口和最大输出 Token。
- 再次拉取模型后保留当前自定义 ID。
