## 0. 一页纸

- **第一个用户 = B**：有图、有科学问题，但**没有流程能力**的研究者（非计算影像专家）。
- **痛（hair on fire）**：不是"更快一点"，而是"今天根本做不了 / 得等三个月合作者或核设施"。
- **第一个楔子场景**：**超声**（刻意选非荧光；病理 WSI 留作后续）；具体任务端点待定（TODO）。
- **产品形态（已决）**：MVP **部署在个人电脑（本地 / 桌面）**，重算力经 **API 调用**处理；云不是终态。
- **冷启动燃料**：先用**公开多中心数据集**（有 ground truth），以 **leave-one-center-out 外部验证**为最强证明。
- **验证哲学**：对 B 重新定义"验证"；硬验证归环境；**信任 = 透明 + 可复现 + 校准过的不确定**，不是 B 去判断像素对错。
- **飞轮两桶油**：公开 / 专家种子（点火）+ B 的弱合理性信号（规模化）——别指望 B 一个人点火。

## 1. 目标用户与场景

### 1.1 首要用户画像 · B
- **是谁**：做回顾性研究的病理 / 临床 / 生物研究者，手里有一批图像和一个明确的科学问题。
- **缺什么**：不会写 ImageJ 宏 / QuPath Groovy / Python；团队里没有计算影像的人。
- **今天的替代方案**：等合作者（数周~数月）、塞给核设施排队、或**放弃这个分析**。
- **为什么不是计算影像专家做首用户**：他们免费工具够用、没有痛，不会为 pre-alpha 换工具。B 才是"自然语言能救、免费工具救不了"的人。
- **B 的固有风险**：B **判断不了分割对错**——这是本条路线的命门，直接决定验证与飞轮怎么设计（见 §3.3 / §3.4）。

### 1.2 首个楔子场景
- **模态**：**超声**（首个楔子）；病理 WSI 留作后续扩展。
- **具体任务端点**：TODO——需定一个具体的"分割 + 测量"端点（例：某结构分割 + 尺寸 / 形态测量）。
- **选它的理由**：① 有公开（含多中心）数据集可冷启动；② B 的痛真实；③ 免费工具救不了 B。
- **产品形态**：MVP 本地 / 桌面部署，重算力经 API 调用（见 §4）。

## 2. 核心用例 / 用户故事

- **主用例**：B 用自然语言描述研究目标 → 环境规划 → 分割 / 测量 → **验证** → 交回结构化洞察 + provenance。
- **"低风险试一把"用例（信任的第一步）**：先在 B 数据的一个小子集上跑；环境**如实标出存疑项**；B 花十分钟点选核对几张，确认"它说有把握的确实对"→ 建立信任。**首次交付不是"给你 200 张的答案"，而是"给你一个能低成本自证一次的理由"。**
- **无代码修正用例**：B 通过点选 / 圈画（非脚本）修正 → 回流飞轮。

## 3. 功能需求（按环境四层）

### 3.1 表征层（眼）
- 解码目标模态（WSI / 超声）→ 统一的可计算表征。
- 支持公开多中心数据集的格式与读取。
- TODO：明确首批要吃的格式 / 分辨率 / 尺度元数据。

### 3.2 动作层（手 · 器械）
- 分割 / 测量 / 重建作为一等操作，带**单位、尺度、校准**与模态护栏。
- 集成成熟模型（Cellpose-SAM / micro-SAM / 病理基础模型等），**不自研 SOTA 分割器**。
- **无代码修正手势**（点选 / 圈画，非脚本）——对 B 是刚需，不是加分项。
- TODO：首个任务端点对应的具体测量原语清单。

### 3.3 验证层（裁判）——本楔子的重心
- **多方法一致性 / 分歧暴露**：跑多个方法，一致处高置信，分歧处标记。
- **校准过的不确定信号**：用公开 ground truth 校准——保证"环境说有把握的地方确实对、说存疑的地方确实容易错"。这是 B 能信任、且环境知道"哪些自己扛、哪些递给 B"的前提。
- **provenance / 可重跑 / 审计轨迹**：每个结果可辩护、可复现。
- **leave-one-center-out 外部验证**：作为可发表 / 可引用的信任资产，不只是内部 QA。

### 3.4 记忆层（飞轮）
- 结构化捕获：意图 → 流程 → 结果 → **人工校正** → provenance。
- 校正回流：接纳"专家种子"（点火）与"B 的弱合理性信号"（规模化）两类燃料。
- 首个领域评测集：以公开多中心数据构建，正对约 58% 可靠性天花板。

## 4. 非功能需求

- **可复现、可审计**：默认产出，不是附加项。
- **不确定必须校准且诚实**：不甩黑箱掩膜；但也不能把专业判断过度甩回给 B（见 §7 开放问题）。
- **产品形态（已决）**：MVP 部署在**个人电脑（本地 / 桌面壳，如 Tauri）**；重算力（分割 / 大模型）经 **API 调用**外部完成，本地不强依赖 GPU。**云不是终态**，只是可选部署目标之一。
- **数据出本机的取舍**：API 算力意味着图像 / 派生特征会离开本机——严格"数据不出院"场景需兜底方案（纯本地 / WASM 跑轻活），列入 §7 开放问题。
- **部署边界**：研究，非临床。

## 7. 开放问题 / 风险（来自 brainstorm，尚未解决）

1. **agent 意图理解是独立失败面**：多中心分割 CV 证明"手和眼跨分布靠谱"，但测不到"大脑有没有听懂 B 的人话"。需单独的意图评测（TODO）。
2. **切换 ≠ 正确**：证明结果对，不等于 B 放弃 QuPath；采用本身要单独验证。
3. **触达问题**：B 怎么被我们找到 / 触达？——本轮完全未探讨，是明显缺口。
4. **不确定的分寸**：诚实暴露不确定能建信任，但暴露过头就是把最难的判断甩回给"做不了的人"。这条线画在哪，待定。
5. **具体任务端点、v0 必须范围、各项量化阈值**：均未拍板。
