# 09 · 基本对话 Docker 发行包

## 0. 文档状态
- 状态：implemented
- 日期：2026-09-06
- 依据：用户确认基本对话、Docker 一键启动、保留底层实现且不装载专用模型。

## 1. 本 SDD 负责什么
对话发行模式、可见入口、无领域工具的 Agent、Docker 启停与持久化。
## 2. 本 SDD 不负责什么
落地页、插件市场、专用模型安装、医学分析验收、自动发布外部镜像。
## 3. 当前阶段目标
仅安装 Docker 的机器可运行预构建镜像，配置模型连接后完成对话，重启保留历史。
## 4. 输入来源
浏览器输入文本及现有对话附件、用户自己的模型 API 配置；不注入开发机密钥。
## 5. 输出结果
流式回复、可管理的会话历史、Compose 启动包、双语 README。
## 6. 核心流程
下载启动包 → 检查 Docker → 拉镜像（离线包先 load）→ 启动 Agent 和 Web → 健康检查 → 打开浏览器 → 配置连接 → 对话。
## 7. 核心规则
- 默认 chat 发行模式；完整实验界面通过开发构建显式 full 模式保留。
- chat 不显示工作台、图像舞台、文件/图谱、领域示例卡、工具权限选择器。
- chat 不请求 Python 后端、不注册领域工具、不在提示词声明工具可用，也不发送旧查看器上下文。
- 对话附件沿用已有协议，依赖用户配置的视觉模型，不启用分割模型。
- 已缓存 workbench 模式在 chat 回退 focus；切换动作、快捷键不能重新进入。
- Docker 仅运行静态 Web 和 Node Agent；Python 后端、science-core 和专用模型实现留在源码，发行包不装载。
- 仅绑定宿主机回环端口；Agent 内部容器监听可配置，宿主不单独发布 Agent 端口。
## 8. 涉及对象
App、会话视图、session store、快捷键、HarnessRegistry、运行时启动配置、Docker 配置及启动脚本。
## 9. 数据或字段要求
VITE_GLAUX_EDITION / GLAUX_EDITION 为 chat（默认）或 full（开发）；无效值拒绝。
GLAUX_AGENT_HOST 默认为 127.0.0.1，容器显式设 0.0.0.0。
Agent SQLite 存在具名卷；连接配置仍按现有协议存浏览器 localStorage，端口/浏览器变化不会迁移此配置。
## 10. 幂等规则
重复启动复用同一 Compose 项目与卷；停止/重建不得删除卷。
## 11. 状态或生命周期规则
健康检查通过才打开浏览器；停止显式执行 stop 脚本，关闭浏览器不等于停止服务。
## 12. 审计或事件规则
保留现有会话与 SSE 协议；不记录凭据；启动失败可查看容器日志。
## 13. 异常和人工处理
Docker 未运行、拉取失败、端口冲突、启动超时给出可操作错误；不自动删除用户数据。
## 14. 与其他 SDD 的调用关系
沿用 00 对话协议；chat 模式覆盖 01 的双模式入口、05 的领域快捷键及 02/03 的工具暴露规则；full 保留原契约。
## 15. 验收标准
- [x] chat 首屏无领域入口，旧缓存与快捷键不能进入工作台。
- [x] chat 零 Python API 请求，所有权限和视觉配置下领域工具均为空。
- [x] full 模式回归保持；文本/附件、流式、停止、历史管理仍可用。
- [x] 镜像从锁文件构建，不含专用模型或个人数据。
- [x] Compose 健康检查通过，代理 SSE 可用，重建后会话仍在。
- [x] 启停脚本检查失败并保留数据；启动包含 README、Compose 和平台脚本。
- [ ] 发布前在目标平台、公开镜像匿名拉取及真实模型对话完成验收。
