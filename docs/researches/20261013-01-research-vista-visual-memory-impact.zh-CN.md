# VISTA 视觉记忆调研与 Glaux 设计影响评估

日期：2026-10-13。范围：论文方法与证据、Atlas、图像观察、上下文裁剪、视频证据及运行轨迹。

本文记录调研结论和候选改进，不冻结新契约，不代表相关能力已经实现或立项。当前行为以活文档 SDD 和代码为准。未运行 VISTA，也未进行 Glaux 真实模型对照评测。

## 1. 结论与影响程度

**总体影响为中等：增强当前架构中的历史观测访问能力，不需要改变产品定位或重建 Atlas。**

- **定位影响低，方向支持强**：视觉输入的组织、取回与检查属于 harness 的职责，与 Glaux 纲领一致。论文没有验证 Glaux 的物理测量、领域正确性或科学复现能力。
- **Atlas 核心设计影响低**：跨任务参考案例与当前任务历史观测职责不同。继续保留原图、ROI、标签、描述和人工修订；没有依据转向视觉向量检索或自动收录全部运行记录。
- **历史观测访问影响中高**：目前有图像存储和重新取图能力，但缺少独立于当前焦点、跨命令可用的历史观测入口。应优先验证这项缺口。
- **视频观察策略影响中高**：现有源指纹、区间和证据引用可复用；“先记文字、后续依笔记作答”的策略应允许按需回看和局部核验。
- **实施影响取决于复现目标**：按旧参数重新读取源数据为中等规模增量；精确返回当时发给模型的画面，则涉及渲染、叠加版本和产物保留，影响高。当前不足以给出人日估计。

影响分级：低表示现有边界成立，仅需验证或局部补充；中表示需要扩展已有模块和相关契约；高表示跨组件改变寻址、持久化或生命周期。中高表示技术基础可复用，但需先澄清语义。

## 2. 论文方法与实验依据

论文：[VISTA: A Visual Harness for Reasoning in an Interactive World](https://arxiv.org/abs/2610.02200)，2026-10-01 发布的 v1。作者：Qiushi Han、Keya Hu、Linlu Qiu、Cathy Wu、Kaiming He。本文固定引用 [v1 全文](https://arxiv.org/html/2610.02200v1)。

方法：保存环境返回的原始帧，包括动画中间帧；模型按需取历史帧、放大区域、读取像素，并维护规则与工作笔记。“无损”指外部保存的观测，不指模型内部表征。[§3](https://arxiv.org/html/2610.02200v1#S3)

最相关的消融如下；均为 GPT-5.6 Sol、max 推理设置下的 ARC-AGI-3 RHAE 分数，不是 Glaux 准确率：

| 配置 | RHAE |
| --- | ---: |
| 连续对话与上下文压缩 | 65.82 |
| 再加规则与工作笔记 | 70.05 |
| 再加视觉记忆与主动检查 | 94.10 |
| 再加精确像素读取 | 99.00 |

来源：[§4.3，Figure 5](https://arxiv.org/html/2610.02200v1#S4.SS3)。这些结果支持进一步验证视觉回看，但不能把增益全部归因于“存图”一个因素。

边界：公开游戏存在训练污染可能；官方基线与完整方案的预算、推理设置等并不完全相同。游戏结果不能直接证明领域案例检索有效。[§4–6](https://arxiv.org/html/2610.02200v1#S4)

## 3. 与 Atlas 的共同点和职责差异

| 维度 | VISTA 的视觉记忆 | Glaux Atlas 当前设计 |
| --- | --- | --- |
| 内容 | 本次交互经历的观测 | 用户导入的跨任务图文案例 |
| 目的 | 回看状态与遗漏细节 | 提供参考图例和领域先验 |
| 访问方式 | 帧与区域检查 | 标签／文本召回，再选择案例看图 |
| 管理方式 | 随交互记录 | 人工整理、修订、下架与引用保护 |

共同原则是让模型在判断时能够取得图像，而非只取得对图像的描述。Atlas 已把描述用作检索依据，并把选中案例的图像交给模型；它不是仅有文字摘要的知识库。

职责差异决定两类内容不宜直接合并。任务中的误判、探索中间结果和未确认标注不能因“保存过”而成为参考先验。若以后需要将观测转成 Atlas 案例，应单独定义人工选择、来源与审核流程；本次调研不改变 [SDD 03](../sdd/feats/03-atlas/README.md) 的非目标和策展边界。

更准确的关系是：Atlas 提供外部参考；历史观测提供本次分析证据；两者可供模型对照，但参考案例不能替代用户数据的证据。

## 4. 当前实现核对

以下结论来自 2026-10-13 工作区代码与活文档的静态检查，不构成端到端验收。

| 能力 | 当前事实与依据 | 缺口或限制 |
| --- | --- | --- |
| 按需看图与放大 | [`view-image.ts`](../../agent-runtime/src/pi/tools/view-image.ts) 支持对象区域与标注叠加；[`observation/index.ts`](../../agent-runtime/src/observation/index.ts) 返回坐标参照。见 [SDD 22 §7](../sdd/feats/22-agent-visual-inspection/README.md) | 观察的对象和索引取自查看器焦点；工具参数不能指定历史观测 |
| 视图编号 | [`view-registry.ts`](../../agent-runtime/src/pi/tools/view-registry.ts) 按命令登记 `v1`、`v2`，保存 `ReferenceFrame` 与区域 | 用于坐标换算，命令结束即释放；不是跨命令的观测标识 |
| 图像上下文裁剪 | [`context-pruning.ts`](../../agent-runtime/src/plugins/context-pruning.ts) 只保留最近 4 个含图像的工具结果，较早图像替换为文字；不改会话存储、不裁剪用户附件。见 [SDD 15 §7.9](../sdd/feats/15-agent-plugins-permissions/README.md) | 提示“再次调用工具”不能保证回到同一画面；图像仍在存储也不等于模型能按历史标识重新取回 |
| Atlas 图像检索 | [`select.ts`](../../agent-runtime/src/atlas/select.ts) 召回最多 10 条，候选较多且有目标图时由 VLM 选择；[`consult-atlas.ts`](../../agent-runtime/src/pi/tools/consult-atlas.ts) 返回案例裁剪图与文字 | 重新检索可能返回不同案例；工具没有按指定案例 id 重开、放大原图的参数 |
| 原图与案例维护 | [`atlas/store.py`](../../backend/app/atlas/store.py) 保存图像引用和摘要；SDD 03 允许修改 ROI、标签、图注，被引用案例不能硬删除 | 禁止删除保护引用存在性，不保证被引用案例的内容永远不变；当前 id 不等于案例版本 |
| 视频观察与证据 | [`video-turn.ts`](../../agent-runtime/src/pi/video-turn.ts) 记录源指纹、区间、编码、观测 id，并检查字节摘要；见 [SDD 11 §7–10](../sdd/feats/11-video-understanding-harness/README.md) | 本轮证据校验依赖本轮观测表；持久化元数据不自动提供跨轮重查或重用证据的工具 |
| 视频媒体上下文 | [`tools/video.ts`](../../agent-runtime/src/pi/tools/video.ts) 要求首次看到媒体时记录所见所闻；SDD 11 允许再次观察，但后续提示主要引导依笔记作答 | 未发现的细节不会自动进入笔记；再次观察仍消耗原有预算 |
| 运行轨迹 | [SDD 21 §7](../sdd/feats/21-run-trajectory/README.md) 提供调用、裁剪与上下文结构；展示图像类型和字节数 | 轨迹主要供人审查，不是模型的历史图像读取工具 |

因此，上一次讨论中的“上下文之外保存证据”需要拆成三个事实：源数据可读、会话有记录、模型有可调用的历史访问路径。当前前两者有不同程度的基础，第三者尚未完整闭环。

## 5. 对设计的分项影响

| 设计面 | 影响程度 | 建议及边界 |
| --- | --- | --- |
| 纲领与三进程分工 | 低 | 保持模型在 runtime、数据与科学能力在 backend／science-core；观察访问可在现有分层内扩展 |
| Atlas 存储与召回 | 低 | 保留 LanceDB、标签／文本召回和原图。论文不足以推翻当前选型 |
| Atlas 案例复查 | 中 | 验证按已引用案例重开及放大是否有收益；保留外发许可，不通过历史入口绕过限制 |
| 当前图像空间检查 | 低 | ROI 放大、无标注原图与复核已存在，先评测实际使用效果 |
| 历史图像时间访问 | 中高 | 候选能力为跨命令列举与回看已观察内容；历史观测标识应与临时坐标换算的 `view_id` 分开 |
| 上下文裁剪 | 中 | 继续保留有界媒体上下文；补充可恢复的引用和明确访问方式。没有依据直接取消裁剪或提高到无限保留 |
| 视频观察策略 | 中高 | 保留原生音画、PTS、指纹与预算；让模型在细节不确定时重新观察指定区间。历史回看和旧证据可直接提交是两项不同契约 |
| 轨迹与科学复现 | 中；精确画面重放为高 | 关联实际观察内容及其版本。区分重新生成视图与精确取回当时的视图 |
| 标定、任务注册表、验证器 | 低 | 像素读取不等于带单位测量；VLM 判断仍不能替代注册表任务或人工核验 |
| 会话底座与 Pi 升级 | 低 | 历史观察能力没有显示出必须升级底座的依赖；不改变现有 [Pi 升级评估](20261005-01-tech-pi-1-upgrade-impact.zh-CN.md) |

### 5.1 关键决策：重新读取源数据，还是精确重放历史画面

二者不能用同一个“无损回看”承诺概括：

- **源数据复查**：记住源版本、对象索引、区域、显示参数，再生成视图。适合不可变源文件；可复用现有取帧能力，但重新叠加的标注可能已改变。
- **历史画面重放**：取回当时实际发给模型的媒体字节及坐标、叠加状态。更适合核对“模型当时究竟看到了什么”，需要产物版本与保留策略。

当前 [`objects.py`](../../backend/app/routers/objects.py) 的 `/frame` 接口依据现有对象与标注生成画面，没有与视频接口等同的 `source_sha256` 请求校验；仅凭对象 id、区域重新取图，不能声称已复现过去的画面。CT 窗宽窗位、WSI 层级、标注变化和编码版本也会影响显示。

建议先验证源数据复查的收益，再决定哪些场景必须保存历史画面。用户删除或替换源文件后应明确报告失效；不可静默把新画面当作旧证据。精确重放若成为目标，需单独评估保存成本和相关生命周期契约。

### 5.2 视频不能照搬游戏帧存储

Glaux 的原始视频本来就可作为历史数据源；再把每一帧保存一份会增加重复存储。候选路径是保留源指纹与源时间，按需取区间或帧；是否保留模型实际接收的编码片段由复现要求决定。

SDD 11 目前明确只持久化非媒体元数据，短片段缓存不承担事实存储。若选择保存历史媒体，必须先修订此边界，不能把它作为透明缓存优化落地。视觉局部核验也不能用静态帧代替需要声音的证据。

## 6. 建议顺序与评测方案

以下为候选工作顺序，尚未立项；优先级指验证价值，不是当前缺陷的严重等级。

1. **先建立基线**：记录现有工具在长任务中因裁剪、焦点切换、遗忘区域而失败的实例。继续完成 Atlas 原有固定 TEM 样本的有／无图谱定位评测，分别检验外部案例和内部历史观察的收益。
2. **验证历史访问**：以不可变图像和视频为小范围，测试按历史引用取回观察内容，跨命令与上下文压缩后仍可访问。先区分源数据复查和精确画面重放，再设计契约。
3. **验证案例复查及视频回看**：对已引用案例局部细节、过去视频区间的遗漏信息做对照；确认收益后再调整工具和提示词。
4. **最后扩展复现与版本管理**：当标注变化、源替换或跨重启重放确有需求时，再决定历史画面、案例版本与保留策略。

建议使用三类固定任务：

| 任务 | 需要回答的问题 | 控制与指标 |
| --- | --- | --- |
| 图像／WSI 局部比较 | 观察多个区域后，能否回到最早区域核对细节？ | 固定源、问题与人工区域；衡量正确率、区域定位、回看成功率 |
| Atlas 参考对照 | 查过案例后，能否重开指定案例确认细节，而非依赖摘要？ | 固定案例集；分开比较无 Atlas、现有 Atlas、支持案例复查的 Atlas；衡量 IoU 与误判 |
| 视频时间对照 | 多次观察后，能否核对先前区间的动作、位置或声音？ | 固定源时间与人工答案；衡量事实正确率、时间／区域匹配、证据支持率 |

所有方案固定模型版本、推理设置、任务样本和总预算，多次重复以观察波动；报告 token、媒体字节、调用次数、时延与失败类型。不要让更大预算成为“历史访问有效”的混杂因素。

工程验证至少覆盖：第 5 个含图工具结果被裁剪后仍可重查；焦点切换后回看原对象；命令结束／压缩后引用仍有效；源版本改变时拒绝错误重放；项目权限与 Atlas 外发许可继续生效。重启恢复、精确字节一致性只在相应目标被纳入契约后作为验收项。

## 7. 后续需要承接的规范

本报告不修改 SDD 状态。若采纳历史观测访问方向，应先冻结访问范围、版本、恢复、预算、权限与保留语义，再推进规范：

- [SDD 10 对象收敛](../sdd/feats/10-object-convergence/README.md)：源版本、区域与显示参数的复查依据。
- [SDD 22 看图与复核](../sdd/feats/22-agent-visual-inspection/README.md)：当前视图与历史观测的分工；临时 `view_id` 的坐标语义。
- [SDD 15 插件与权限](../sdd/feats/15-agent-plugins-permissions/README.md)：裁剪占位及历史读取的权限归属。
- [SDD 19 上下文管理](../sdd/feats/19-context-management/README.md)：跨压缩的历史引用可见性。
- [SDD 21 运行轨迹](../sdd/feats/21-run-trajectory/README.md)：实际输入与观察引用的审查关联。
- [SDD 11 视频 harness](../sdd/feats/11-video-understanding-harness/README.md)：回看预算、跨轮证据校验及媒体保留边界。
- [SDD 03 Atlas](../sdd/feats/03-atlas/README.md)：仅在增加指定案例复查或版本保护时修订。

若历史观察成为独立、跨模态的生命周期能力，宜另立 Feature SDD 并由上述规范引用；不要在多个 SDD 中分别定义同一套观察标识。本次仅提出分工建议，具体拆分待范围收敛。
